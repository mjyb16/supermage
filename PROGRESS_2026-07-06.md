# supermage — change report, week of 2026-06-29 → 2026-07-06

What changed in the package this week, why, and how each change was
validated. Audience: someone who knows the physics and will consume these
APIs; commit hashes are on `main` (pushed; verified 2026-07-06). Context
commit just before the week: `5468ee6` (2026-06-24) — Core-Sérsic
`core_sersic_torch_1d` moved to log-space (`logaddexp`) evaluation after fp32
overflow of R^α was shown to inflate profiles ×462 and forge spurious
"extended R_e" posterior modes. Do not revert to direct `torch.pow`.

## Commits this week

### `e9a46e2` / `fea9cd3` — "Adding code for final run" (2026-07-02)
The corrected-pipeline core, implementing NGC 4697 code-review fixes 1, 3, 4, 6
(numbering as in `sknkwx .../ngc4697/publication_run_nautilus/README.md`):

- **`utils/likelihood.py`** — float64 χ² reductions everywhere
  (`resid.double()` before square/sum; fp32 quantization had produced
  nested-sampling logL plateaus → "Distances are not positive" crashes), and
  a **half-plane branch** in `load_raw_data`: accepts `half_plane=True` npz
  (Hermitian slab), asserts slab shape and zeroed masked cells, reads
  `taper_map`, and sets `n_chi_half = sum(mask)` (vs `sum(mask)/2` for legacy
  full-plane files — the Hermitian double-count fix).
- **`simulators/visibility_cube.py`** — BREAKING: the
  `apodization_map`/`deapod_*` parameters are DELETED. The forward now
  **multiplies** the padded image by `image_taper_map` before the FFT (the
  legacy divide-by-apodization convention was inverted); new
  `output_half_plane=True` returns the masked Hermitian slab matching the
  data files; `dish_diameter=None` disables the PB; `line` is in **Hz**.
- **`utils/primary_beams.py`** — BREAKING: `gaussian_pb(freq_hz=...)`
  validates its input is Hz (raises outside 1e8–1e13) and takes
  `fwhm_factor` (default **1.13**·λ/D, the ALMA effective response; the old
  hard-coded 1.02 and the silent GHz acceptance are gone — GHz input used to
  make the PB evaluate ≈flat). `casa_airy_beam` remains known-broken and
  documented as such.
- **`simulators/velocity_scatter.py`** (new, shared by `AnalyticInverse` and
  `AnalyticLens`) — out-of-band velocity-scatter weights are **zeroed**
  instead of index-clamped. The clamp had folded out-of-range Keplerian flux
  into the edge channels, creating a spurious m_bh-dependent point source in
  the band-edge channels of both the direct and lensed cubes.

### `d1483b8` — "Docs and bug fix in lens" (2026-07-05)
- **`simulators/lensed_cube.py::AnalyticLens.forward`** — the one functional
  change in an otherwise-docs commit: a `_bad = ~(isfinite(I_map) &
  isfinite(v_los))` guard that zeroes both maps at non-finite pixels.
  Mechanism of the bug it fixes: pixels within ~1 hi-res pixel of the EPL
  lens center overflow the fp32 deflection → cos θ = inf/inf = NaN → the NaN
  spreads to the WHOLE cube through flux normalization → the sampler rejects
  an otherwise-valid draw (~1/8 of random draws at oversamp 3; with odd
  oversamp × odd grid the center node fails every time). The zeroing is
  physically exact (those pixels map to infinite source radius). Validated:
  64/64 random draws finite (was ~7/8); pathological draws still rejected;
  clean-point logL bitwise unchanged. The sknkwx ID141 driver preflight
  source-checks this guard.
- Full docstring pass across the package; tutorial notebooks 01–04; the
  malformed `line: 230.538` annotation fixed to `line: float`.

## Migration notes for downstream code

Anything constructed against the pre-July API breaks loudly (deliberate):
`VisibilityCubePadded(apodization_map=...)` → TypeError;
`gaussian_pb(freq_ghz_array)` → ValueError. Legacy sknkwx notebooks
(hengyue_latest, mass_sheet_degeneracy) still build GHz models and will fail
until touched. Frozen pipelines (final_nautilus) pin pre-fix SHAs in their
PROVENANCE.md and are not meant to run against HEAD.
